# rubert-mini-frida в OpenVINO IR

Модель эмбеддингов индексатора. В поставку этот файл не попадает (фильтр `_MODEL_EXCLUDE`
в `main.spec`), он для разработчиков и проверки ИБ.

## Происхождение

- Источник: https://huggingface.co/sergeyzh/rubert-mini-frida, ревизия
  `32a82388a9f99c99eca74494731f7ee6e9a9fe3a`, веса скачаны в формате safetensors.
- Лицензия: MIT. Это дистилляция ai-forever/FRIDA (учитель, 1536 чисел, 24 слоя) в
  архитектуру rubert-tiny2 — текст лицензии в `debian/copyright`.
- Архитектура: BERT, 7 слоёв × 312 (у rubert-tiny2_002 — 3 × 312), токенизатор и словарь
  rubert-tiny2 (83 828 токенов). Вектор — 312 чисел, mean-пулинг (`1_Pooling/config.json`),
  префиксы `search_query: ` и `search_document: ` (`config_sentence_transformers.json`) —
  энкодер берёт их из этих файлов.

## Конвертация (05.10.2026, стенд `lib-local-rag-eval/work/models/convert.py`)

- OpenVINO 2026.3.1, openvino-tokenizers 2026.3.1.0, optimum-intel 2.2.0, nncf 3.4.0.
- FP32 IR через sentence-transformers (`backend="openvino"`), затем сжатие только весов:
  `nncf.compress_weights(mode=INT8_ASYM)`, активации остаются в FP32. Статическое INT8 с
  калибровкой (как у rubert-tiny2_002) mini-frida не годится: косинус с FP32 — 0,94.
- Токенизатор: `openvino_tokenizers.convert_tokenizer`; токены совпадают с оригиналом
  (32 из 32 проверочных фраз).
- Проверка: OpenVINO FP32 совпадает с исходной torch-моделью (косинус 1,0000 на 64
  запросах и 64 фрагментах); INT8 весов против FP32 — средний косинус 0,9994, минимальный 0,9992.
- SHA-256 весов: `a54d8c4eb60db1dd3b4dc7ecf412a0b58aa0c897e18ccfb2f33bb4fa1f40e696`.

## Качество и скорость на стенде

Против rubert-tiny2_002, выдача как в 1.0.9, документы без оценки убраны из выдачи
(сжатые списки), модель в FP32 (INT8 весов от неё неотличим):

| | Рабочая часть (1 332) | Контрольная часть (650) |
|---|---|---|
| Гибрид, nDCG@10 | +0,003 [−0,005…+0,011] | +0,003 [−0,007…+0,014] |
| Гибрид, Hit@1 | +0,027 [+0,003…+0,051] | −0,022 [−0,052…+0,006] |
| Только вектор, nDCG@10 | +0,044 [+0,032…+0,055] | +0,038 [+0,023…+0,054] |

Скорость эмбеддинга на Apple M1 (4 потока, батч 8): 15,4 фрагмента в секунду против 54 у
rubert-tiny2_002 — примерно в 3,5 раза медленнее.
