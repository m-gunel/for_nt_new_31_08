# MCP-мост LocalRAG

Мост отдаёт агенту то, чего у того нет своими силами: **семантический поиск по
локальному индексу** и **состояние индексации**. Собственной логики поиска в нём
нет — он транслирует вызовы инструментов в HTTP-запросы к сайдкару LocalRAG.

```
Агент (GigaTool / любой MCP-клиент)
        │  MCP stdio: JSON-RPC построчно через stdin/stdout
        ▼
┌──────────────────────────────┐
│  mcp_launcher.sh             │  выбирает интерпретатор
│   └─ mcp_server.py           │  мост, чистый stdlib
└──────────────┬───────────────┘
               │  HTTP 127.0.0.1:<порт из ~/.files-search/port>
               ▼
┌──────────────────────────────┐
│  LocalRAG sidecar (main.py)  │  /search, /status, /config
└──────────────────────────────┘
```

Мост не имеет зависимостей при импорте — только stdlib. Это условие поставки: в
дистрибутив он уезжает отдельными файлами и запускается на системном `python3`,
без venv репозитория. Чтение файлов устроено в два слоя: офисные форматы и pdf
мост запрашивает у демона (`POST /api/v1/read_file`) — в бинаре демона вшиты
`pymupdf` (pdf) и конвертер Р7-Офиса (легаси `.doc`/`.xls`). Если демон
недоступен или старой версии без этой ручки, OOXML (`.docx`, `.pptx`, `.xlsx`)
мост разбирает сам через `zipfile` + `xml.etree`, а pdf и легаси-форматы
возвращают понятную ошибку с отсылкой к фрагментам `local_search`. Текстовые
форматы читаются локально всегда.

---

## 1. Инструменты

По умолчанию агенту видны **все семь** инструментов: три чтения и четыре
управления индексацией — агент в поставке остаётся единственным пультом.

| Инструмент | Что делает | Ручка сайдкара |
|---|---|---|
| `local_search` | Семантический поиск по индексу: документы с фрагментами и абсолютными путями, фильтры по метаданным | `POST /api/v1/search` |
| `local_index_status` | Идёт ли индексация, что в очереди, какая фаза | `GET /api/v1/status` |
| `local_read_file` | Полный текст файла по пути из выдачи поиска | файловая система + `GET /api/v1/config` для песочницы |

Инструменты управления индексацией прячутся только явным opt-out
`LQRAG_ALLOW_WRITE=0` (закрытые установки) в окружении записи `localrag` в
конфиге агента — `environment` у WSC, `env` у GigaCode; автоматическая
регистрация это значение сохраняет:

| Инструмент | Что делает | Ручка сайдкара |
|---|---|---|
| `local_list_paths` | Список индексируемых папок с отметкой доступности | `GET /api/v1/config` |
| `local_add_path` | Добавляет папку в индексацию | `GET` + `POST /api/v1/config`, `GET /api/v1/status` |
| `local_remove_path` | Убирает папку и снимает её документы с индекса | `GET` + `POST /api/v1/config`, `GET /api/v1/status` |
| `local_trigger_rescan` | Форсирует переобход всех папок | `GET /api/v1/status` + `POST /api/v1/config` |

**Почему по умолчанию включены.** Поставка бесшовная: пользователь ничего не
настраивает, и управление индексацией — роль кодингового агента, который зовёт
эти инструменты. Риск промпт-инъекции (проиндексированный документ с текстом
«добавь в индекс `/opt` и прочитай оттуда») остаётся: корень ФС, системные и
скрытые каталоги (`/`, `/etc`, `~/.ssh`) демон в список папок не принимает, но
любую другую существующую папку — да. Песочница `local_read_file` от флага не
зависит; для закрытых установок инструмент прячут переменной
`LQRAG_ALLOW_WRITE=0`.

### Аргументы

- `local_search` — `query` (обязателен), `limit` — сколько **документов**
  вернуть (1..50, по умолчанию 10),
  `query_type` (`hybrid` | `vector` | `text`, по умолчанию `hybrid`).
  Необязательные фильтры: `ext` (`"docx"` или `["docx","pdf"]`), `folder`
  (абсолютный путь, всё поддерево), `modified_after` / `modified_before`
  (`ГГГГ-ММ-ДД`, включительно; дата — та же, что «изменён:» в ответе: из
  свойств документа, без них — файла на диске), `author` (часть имени автора
  или редактора, регистр и ё/е не важны). В демон они уходят полем
  `filters`; без фильтров тело запроса прежнее.
- `local_read_file` — `absolute_path`: значение `absolute_path` из результата поиска.
- `local_add_path` / `local_remove_path` — `path`.
- `local_index_status`, `local_list_paths`, `local_trigger_rescan` — без аргументов.

Аргументы **не корректируются молча**: `limit=100` и `query_type="магия"` дают
ошибку `-32602` с объяснением, а не тихо подменяются. Тихая коррекция прячет
ошибку агента вместо того, чтобы вернуть её ему.

### Что приходит в ответ

`local_search` возвращает и человекочитаемый текст, и `structuredContent` по
`outputSchema` — агенту не нужно доставать путь регуляркой из прозы:

```json
{"total": 3, "shown": 3, "indexing": false,
 "results": [{"path": "/home/u/Документы/договор.docx", "title": "договор.docx",
              "type": "file", "score": 0.033, "match": ["card"],
              "chunks": [{"text": "…", "score": 0.033, "page_start": 2}]}]}
```

- `total` — сколько документов вернул демон: каждый документ собран из его
  лучших чанков, их у документа до трёх (`chunks`).
- `score` — оценка поиска. В `hybrid` это оценка RRF (сотые доли), в
  `vector` — минус косинусное расстояние, в `text` — BM25; между режимами
  числа не сравнимы. Порядок ответа: сначала файлы с `name_code`,
  затем по оценке. У файла, найденного только по коду из имени и дочитанного
  вне пула поиска, оценки нет — там `null`.
- `match` — чем ещё документ совпал, кроме фрагментов. `card` — слова запроса
  есть в имени файла или его свойствах (название, автор, редактор, тема,
  ключевые слова, описание): у каждого документа в индексе есть «карточка» из
  этих полей, в индексе прежних версий демон дописывает её сам первым
  проходом индексации. Совпадение полнотекстовое: в `vector` отметки нет.
  `name_code` — код из запроса («Найди файл ЦБ_21», «ЦБ_21.pdf», «5348-У»,
  «obs_286») есть в имени файла; такие файлы идут первыми. В тексте ответа
  это строки «код из имени файла» и «слова запроса есть в имени или свойствах
  файла»; документ, найденный одной карточкой, приходит без фрагментов.

Объём ответа ограничен (`LQRAG_MAX_OUTPUT`, по умолчанию 12 000 символов): без
этого `limit=50`, помноженный на фрагменты, уезжал бы в контекст модели целиком.
Раскладка в бюджет идёт по приоритету: сначала каждому документу — заголовок с
путём, отметки и строка о документе, затем по одному фрагменту, укороченному,
если места мало, и только потом добавочные фрагменты верхним документам.
Длинный документ не обрывает список; фрагменты короче 120 символов не
показываются — при острой нехватке места их получают верхние документы.
Документы выпадают, только если не влезают даже их заголовки: тогда в тексте
появляется «показано N».

### Пустая выдача

Если поиск ничего не нашёл, мост сам спрашивает `/status` и в ответе различает
четыре случая: индексация идёт (документ может появиться позже), индексация
выключена (`POST /api/v1/deactivate` или `/reset`: индекс может быть пуст или
устарел, включается `POST /api/v1/activate`), индексация не идёт (индекс актуален)
и статус узнать не удалось. Это защита от самой частой неверной реакции агента —
уверенного «такого документа нет» во время первой индексации.

## 2. Безопасность `local_read_file`

- Читается ровно то, до чего доходит обход индексатора: **только файлы внутри
  индексируемых папок** (список берётся у сайдкара через `GET /api/v1/config`),
  кроме скрытых файлов и всего, что лежит под скрытыми и служебными каталогами
  ниже корня (`~/.config`, `~/.ssh`, корзина, `node_modules`, `snap` — список в
  `src/indexer/exclude.py`). `..`-обход не проходит; путь через символьную
  ссылку читается так же, как его хранит индекс.
- Если сайдкар недоступен, чтение **запрещается**: границы песочницы неизвестны,
  а открытый доступ ко всей файловой системе хуже отказа.
- Расширения `.env`, `.ini`, `.conf`, `.properties`, `.toml` исключены
  намеренно — в таких файлах лежат токены.
- Ограничение объёма — 40 000 символов на файл.

## 3. Запуск сайдкара

```bash
CONFIG_PATH=cfg/mcp.yml RAG_HOST=127.0.0.1 RAG_PORT=8000 \
  .venv/bin/python main.py > /tmp/rag_mcp.log 2>&1 &
```

- Дождитесь `прогрев завершён за N.N c` — первый прогрев OpenVINO занимает
  40–45 секунд. Строки `Uvicorn running` не будет: `main.py` отдаёт uvicorn
  готовый сокет, и стартовое сообщение тот не печатает. Адрес сообщает
  собственная строка демона `слушаю http://...`.
- Проверка: `curl http://127.0.0.1:8000/api/v1/health` → `{"status":"OK"}`.
- **Хост по умолчанию — `127.0.0.1`** (пустой `RAG_HOST` — тоже он, см.
  `src/bind_host.py`). Слушать внешний интерфейс демон согласится только при
  двух переключателях сразу — `RAG_HOST=<внешний адрес>` и `LQRAG_EXPOSE=1`;
  без второго он отказывается стартовать с объяснением. Клиентам по сети
  нужны ещё имя в `RAG_ALLOWED_HOSTS` и токен агента, а по HTTP токен идёт
  открытым текстом.
- Все ручки, кроме `/health`, требуют токен агента (§5, «Аутентификация на
  демоне»).
- `nice` при старте не применять (зависает компиляция модели OpenVINO); `renice` —
  только после готовности сервера.

Папки для индексации задаются через `POST /api/v1/config`, а не правкой YAML:
при правке YAML в обход API состояние LSM считает файлы уже обработанными, и
обход честно не находит ничего нового (`nothing new`, `total=0`).

**Про автозапуск индексации.** Индексация стартует вместе с демоном — это
штатный режим и разработки (`cfg/mcp.yml`), и поставки (`cfg/distro.yml`, он
же `/etc/lib-local-rag/distro.yml`, `autostart_indexing: true`): поставка
бесшовная, пользователь ничего не активирует. Отладочный обратный режим —
`autostart_indexing: false`: демон поднимается, отвечает на поиск по уже
собранному индексу и ждёт `POST /api/v1/activate`.

## 4. Подключение к агенту

### Автоматически

```bash
python3 scripts/register_mcp.py                    # прописать во все цели
python3 scripts/register_mcp.py --dry-run          # посмотреть результат
python3 scripts/register_mcp.py --doctor           # диагностика, ничего не менять
python3 scripts/register_mcp.py --list             # какие цели известны
python3 scripts/register_mcp.py --target wsc       # только одна цель
python3 scripts/register_mcp.py --remove           # снять при удалении ПО
python3 scripts/register_mcp.py --rotate           # перевыпустить токены агентов
python3 scripts/register_mcp.py --revoke wsc       # отозвать текущий токен агента
python3 scripts/register_mcp.py --forget           # удалить токены во всех домах (uninstall.sh)
```

Целей две, и **схемы у них разные**:

| Цель | Файл | Схема записи |
|---|---|---|
| `wsc` — Workspace Computer | `~/.wsc/config/wsc.json` | `mcp.<имя>`, `command` массивом |
| `gigacode` — GigaCode | `~/.gigacode/settings.json` | `mcpServers.<имя>`, `command` строкой + `args` + `env`, без `type` |

Каталог `~/.config/gigatool/` — легаси: новых записей туда не делается, но
оставшийся там от старых версий невалидный ключ `mcp.servers` вычищается.

Скрипт дописывает запись, сохраняя всё остальное содержимое конфига: другие
MCP-серверы, `permission`, `$schema`, `ide` не затираются. Абсолютный путь к
лаунчеру подставляется сам, повторный запуск ничего не меняет. Свою запись
`localrag` скрипт приводит к эталону, но `enabled` (WSC) и чужие переменные
окружения записи (`environment` у WSC, `env` у GigaCode) — в том числе
`LQRAG_ALLOW_WRITE=0` закрытой установки — оставляет как есть; `--doctor`
считает такую запись верной. Конфиг читается как JSONC (агент допускает
комментарии и висячие запятые), но записывается обычным JSON — комментарии
при перезаписи теряются. Файл переписывается, только когда запись нужно
поменять. Перед первой правкой рядом сохраняется `<файл>.localrag-backup`, а
при следующих перезаписях файла с комментариями — ещё и
`<файл>.localrag-backup-<дата-время>`; где остался прежний текст, скрипт пишет
в stderr. Битый JSON или файл не в UTF-8 скрипт не перезаписывает, а
отказывается работать: там чужие настройки. Права существующего файла
сохраняются. Отказ по одной цели не мешает остальным.

Если каталога агента нет, цель пропускается и **ничего не создаётся**: пустой
`~/.gigacode` под неустановленный плагин — мусор и ложный сигнал.

Найденным агентам скрипт выдаёт токены демона и подписывает запись ярлыком
`LQRAG_AGENT=<агент>` (§5, «Аутентификация на демоне»). Свой конфиг вне
реестра целей — `--config <файл> --agent <имя>`: имя войдёт в ярлык и получит
свой токен.

**Куда пишет.** `~` в таблице — домашний каталог из passwd: там конфиги агентов
графической сессии. Дополнительно скрипт проверяет `$HOME` (у терминала SberOS
это «папка разработчика» `/home/work/ЛОГИН@ДОМЕН`) и SberOS-пару
`/home/work/ЛОГИН@ДОМЕН` и `/home/ДОМЕН@ЛОГИН`. Пишет только туда, где каталог
агента уже есть и принадлежит пользователю. `--home ПУТЬ` (можно повторять) и
`LQRAG_REGISTER_HOMES` заменяют этот поиск явным списком. От root без явного
`--home` или `--allow-root` скрипт не работает: конфиг агента стал бы
собственностью root, и агент перестал бы его переписывать.

Из пакета скрипт вызывают трое: `postinst` при установке (в уже открытых
сессиях, от имени пользователя через `runuser`), пользовательский юнит
`lib-local-rag-mcp-register.service` при входе в сессию и парные `.path`-юниты —
каждый раз, когда агент создал или перезаписал свой конфиг. Только stdlib,
уровень python3.6 — работает на голом системном `python3`.

**Адрес сайдкара в конфиг не пишется**: мост сам читает порт, опубликованный
демоном (`~/.files-search/port`), поэтому запись остаётся верной и после
перезапуска индексатора на другом порту. Это же закрывает требование БТ §4.2 о
динамическом назначении порта — задайте `RAG_PORT=0`, и порт выберет ядро.

### Вручную

Агент запускает мост как локальный процесс:

```json
{
  "mcp": {
    "localrag": {
      "type": "local",
      "command": ["/абсолютный/путь/mcp_launcher.sh"],
      "enabled": true,
      "timeout": 120000,
      "environment": {
        "LQRAG_TIMEOUT": "110",
        "LQRAG_AGENT": "wsc"
      }
    }
  }
}
```

Ключ внутри `mcp` — это **имя сервера**. Вложенности `mcp.servers.<имя>` не
существует: агент прочитает такую запись как сервер с именем `servers`, у
которого нет обязательных `type` и `command`, не пройдёт валидацию и отбросит
**весь** конфиг целиком. Поле окружения называется `environment`, не `env`.
`timeout` нужен явно: умолчание агента — 5000 мс, а прогрев модели занимает
40-45 секунд. `LQRAG_AGENT` — несекретный ярлык для аутентификации на демоне
(§5): сам токен выдаёт `register_mcp.py`, в конфиг он не попадает. Без
выданного токена ручная запись получит от демона 401.

Образцы — [`opencode-config.example.json`](opencode-config.example.json) и
[`gigacode-settings.example.json`](gigacode-settings.example.json).

### Из пакета

Мост лежит в `/usr/lib/lib-local-rag/mcp/`. Регистрировать его руками не нужно:
`postinst` прописывает его сразу при установке в открытых сессиях, юнит
`lib-local-rag-mcp-register.service` — при каждом входе, а парные `.path`-юниты
повторяют регистрацию, когда агент создал или перезаписал свой конфиг. После
установки агентов нужно перезапустить, и при обновлении тоже: мост, запущенный
до установки, не знает своего ярлыка и получает от демона 401.

Проверить мост отдельно, без агента:

```bash
echo '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' \
  | /usr/lib/lib-local-rag/mcp/mcp_launcher.sh
```

Сервер ждёт JSON-RPC на stdin; venv рядом не нужен, лаунчер возьмёт системный
`python3`. Диагностика пишется в stderr, stdout занят протоколом.

Удаление вместе с индексами — `apt purge lib-local-rag`.

## 5. Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LQRAG_URL` | — | Адрес сайдкара. Задан — сильнее всего остального. Не задан — порт берётся из опубликованного файла, иначе `http://127.0.0.1:8000` |
| `LQRAG_PORT_FILE` | `$HOME/.files-search/port`, затем тот же файл в каталоге из passwd | Где искать порт, опубликованный демоном. Задан явно — ищется только в нём |
| `LQRAG_TIMEOUT` | `30` | Таймаут HTTP, секунды |
| `LQRAG_AGENT` | — | Несекретный ярлык агента (`wsc`, `gigacode`): по нему мост берёт токен из `tokens/<агент>.token` рядом с порт-файлом. Ставит `register_mcp.py`, вручную не нужен |
| `LQRAG_TOKEN_FILE` | — | Явный путь к файлу токена; задан — берётся только он, как `LQRAG_PORT_FILE` (тесты, нестандартная установка) |
| `LQRAG_AUTOSTART` | `1` | `0` запрещает мосту поднимать `lib-local-rag.service`, когда демон недоступен |
| `LQRAG_SYSTEMCTL` | `systemctl` из `PATH` | Какой `systemctl` звать для автозапуска (подмена в тестах) |
| `LQRAG_ALLOW_WRITE` | `1` | `0` прячет инструменты управления индексацией (закрытые установки) |
| `LQRAG_MAX_OUTPUT` | `12000` | Бюджет символов на ответ поиска |

### Аутентификация на демоне

Каждая ручка под `/api/v1`, кроме `/health`, требует заголовок
`Authorization: Bearer <токен агента>`; без токена и с чужим токеном ответ
один — 401. Жизненный цикл токена:

- **выдаёт `register_mcp.py`** агентам с найденным конфигом: секрет — в
  `~/.files-search/tokens/<агент>.token` (права 0600), демону — только sha256
  в `~/.files-search/auth.json`. В конфиг агента уходит несекретный ярлык
  `LQRAG_AGENT=<агент>`: конфиги показывают в тикетах и коммитят в
  репозитории, токен там храниться не может. У агента один токен во всех
  домах; повторная регистрация переиспользует действующий. Параллельные
  запуски регистрации ждут друг друга на `~/.files-search/.register.lock`;
- **мост читает токен при каждом запросе** и предъявляет его только своему
  демону: по порт-файлу, опубликованному живым процессом этого пользователя
  (токен — из `tokens/` рядом с этим порт-файлом), или по loopback-адресу из
  `LQRAG_URL` с явным портом — тогда только с явным `LQRAG_TOKEN_FILE`. На
  Linux мост ещё сверяет, что порт слушает процесс этой учётки; чужой
  слушатель — отказ «порт … занят чужим процессом». Запасному
  `http://127.0.0.1:8000` токен не уходит. Битый файл токена — отказ с текстом
  про `--rotate`, содержимое файла в ответ не попадает;
- **демон перечитывает `auth.json`** при смене файла — отзыв и ротация
  доходят до обеих сторон без перезапусков;
- **fail-closed**: нет `auth.json`, пустой, битый или с чужим владельцем —
  доступ закрыт всем, включая наши мосты; для периметра с личными файлами
  «открыто по умолчанию» означало бы, что одна потерянная регистрация
  раскрывает весь индекс;
- **перевыпуск** — `register_mcp.py --rotate`, **отзыв** —
  `register_mcp.py --revoke <агент>` (хэш и файл токена во всех домах).
  Регистрация при отзыве остаётся, и следующая выдаст агенту новый токен:
  это смена секрета, а не запрет агента. Отозванный и перевыпущенный токен
  регистратор помнит (`withdrawn_tokens`) и не вернёт из копии в другом доме;
- выдача текстов файлов и смена состояния логируются демоном **с именем
  агента** — из совпавшего хэша, а не из заголовков клиента.

Если после обновления пакета инструменты отвечают «LocalRAG API вернул 401:
требуется токен агента» — в агенте прежний мост без токена: перезапустите агента.
Ответ «нет действующего токена агента (401)… register_mcp.py --doctor» даёт уже
новый мост: токен не выдан, отозван или не совпал — диагностика из сообщения.

Граница схемы (модель угроз VAS-6850): носители секрета лежат внутри дома
пользователя, поэтому чужой UID и браузерный JS их не читают; процессы того же
UID bearer-схема не различает — эта граница фиксируется как граница ОС и
закрывается только LSM-профилем (отложено).

## 6. Проверка

```bash
# Быстрые тесты моста: протокол и контракт на заглушке сайдкара.
# Ни индекса, ни OpenVINO не требуют.
uv run pytest tests/test_mcp_protocol.py tests/test_mcp_tools_contract.py \
  tests/test_mcp_auth.py -v

# Полный цикл на живом демоне (поднимает его сам, ждёт прогрев модели).
uv run pytest tests/test_mcp_integration.py -m integration -v

# Вручную, без агента:
echo '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | ./mcp_launcher.sh
```

Мост пишет диагностику в **stderr** — в stdout идёт только JSON-RPC.

При недоступном сайдкаре инструменты возвращают `isError: true` с объяснением:
мост не падает и не блокирует агента. Ответы зависят от состояния:

- **демон отвечает 401** — у моста нет действующего токена агента: «нет
  действующего токена агента (401)… перезапустите агент… register_mcp.py
  --doctor». Чаще всего агент не перезапущен после установки (мост стартовал
  без ярлыка `LQRAG_AGENT`). Прежний мост, не перезапущенный после обновления,
  отвечает иначе: «LocalRAG API вернул 401: требуется токен агента»;
- **демон жив** (процесс из `~/.files-search/pid` существует), но соединение
  отвергается — идёт прогрев модели: «индексатор запускается или
  прогревается», systemd мост не трогает;
- **демона нет** — мост просит systemd поднять его (`systemctl --user start
  --no-block lib-local-rag.service`) и сразу отвечает «запускается или
  прогревается», не дожидаясь прогрева. Если попытка не удалась, к ответу
  добавляется «Автозапуск: <причина>»;
- **служба замаскирована** на время установки или обновления пакета — «служба
  временно остановлена, повторите через минуту»;
- **отказы идут дольше ~3 минут** — «индексатор не поднимается» с состоянием
  службы из `systemctl --user show`; повторная попытка запуска не чаще раза в
  3 минуты.

Попытка делается и заранее: на `initialize` мост проверяет `/api/v1/health`.
Если `LQRAG_URL` задан явно, автозапуска нет: демон по такому адресу — не наша
служба. Запросы к сайдкару идут мимо `http_proxy`: он всегда на 127.0.0.1.
