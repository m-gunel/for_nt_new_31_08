# Запуск для тестировщика

Индексатор с MCP-обвязкой. Порядок ниже проверен целиком; если шаг падает —
смотрите таблицу в конце, там разобраны известные случаи.

Это запуск **из исходников** (архив с репозиторием). Проверка установленного
пакета `.deb` устроена иначе, без команд: [docs/RUN-DEB.md](RUN-DEB.md), часть A.

Требуется: SberOS (x86_64), Python 3.12, доступ к зеркалу `sberosc`.

---

## 1. Установка

```bash
unzip lib-local-rag-mcp-*.zip
cd lib-local-rag

# ОБЯЗАТЕЛЬНО перед установкой: в pyproject.toml индекс пакетов прописан с
# плейсхолдером OSC_TOKEN. Подстановку делает только Dockerfile при сборке
# образа, поэтому на обычной машине её нужно выполнить руками — иначе uv
# пойдёт в зеркало с логином "OSC_TOKEN" и получит 401.
sed -i "s/OSC_TOKEN/<ваш токен sberosc>/" pyproject.toml

uv sync --frozen        # ставит РОВНО те версии, что зафиксированы в uv.lock
```

Флаг `--frozen` обязателен: без него состав пакетов резолвится заново по тому,
что лежит в зеркале сегодня, и ваши цифры будут несравнимы с эталонными.

`uv.lock` в репозитории есть. `requirements.lock.txt` нет: он нужен только
для установки без `uv`, и его сначала генерируют на машине с `uv`:
`uv export --no-hashes --format requirements-txt --no-dev -o requirements.lock.txt`.

Без `uv`:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock.txt
```

## 2. Тесты

```bash
uv run pytest -m "not integration" -q
```

Ожидается зелёный прогон целиком. Тесты под маркером `integration` исключены —
им нужно внешнее окружение, они запускаются отдельно на шаге 4.

## 3. Демон

```bash
CONFIG_PATH=cfg/mcp.yml RAG_HOST=127.0.0.1 RAG_PORT=8000 \
  .venv/bin/python main.py > /tmp/rag.log 2>&1 &

curl -s http://127.0.0.1:8000/api/v1/health     # {"status":"OK"}
```

Первый запуск прогревает модель 40–45 секунд — до строки `прогрев завершён за
N.N c` в логе сервис не отвечает. Строки `Uvicorn running` в логе **нет**:
`main.py` передаёт uvicorn уже забинденный сокет, и своё стартовое сообщение
тот в таком режиме не печатает. Ориентир — собственная строка демона
`слушаю http://...`. **`RAG_HOST=127.0.0.1` указывайте явно:** по
умолчанию демон слушает `0.0.0.0`, то есть отдаёт поиск по файлам пользователя
всей сети без авторизации.

Папки для индексации задаются через API, а не правкой YAML:

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/config \
  -H 'Content-Type: application/json' -d "{\"folders\":[\"$HOME/Документы\"]}"

curl -s http://127.0.0.1:8000/api/v1/status     # ждём is_indexing: false
```

При правке YAML в обход API состояние LSM считает файлы уже обработанными, и
обход честно не находит ничего нового (`nothing new`, `total=0`).

## 4. Полный цикл через MCP

```bash
uv run pytest tests/test_mcp_integration.py -v
```

Тест сам поднимает демон на свободном порту со своим временным HOME, создаёт
корпус, добавляет папку через инструмент моста, ждёт индексацию, ищет, читает
найденное и проверяет, что файл вне индексируемых папок прочитать нельзя.
Идёт 2–3 минуты, почти всё — прогрев модели. Ваш рабочий индекс не затрагивается.

## 5. Нагрузочное

```bash
DIR=~/index_test_files ./scripts/nt/check_indexer_fix.sh              # ~1 мин
FILES=150 MINUTES=6 DIR=~/index_test_files ./scripts/nt/smoke_user_path.sh
python3 scripts/nt/mcp_overhead.py --url http://127.0.0.1:8000        # цена моста
```

Полный протокол НТ — `scripts/nt/README.md`.

Критерии для `mcp_overhead.py`: накладные расходы моста по p50 — единицы
миллисекунд, `errors = 0`. Фаза `mcp_burst` показывает, что мост обрабатывает
запросы последовательно: это его свойство, а не поломка.

## 6. Подключение к агенту

Мост запускается агентом как локальный процесс. Проще всего прописать его
скриптом — он сам подставит абсолютный путь и восстановит бит `+x`, если тот
потерялся при распаковке архива:

```bash
python3 scripts/register_mcp.py            # из репозитория
python3 mcp/register_mcp.py                # из распакованного distro.zip
```

Скрипт дописывает запись в конфиги агентов — Workspace Computer
(`~/.wsc/config/wsc.json`) и GigaCode (`~/.gigacode/settings.json`), — не затирая
остальное их содержимое. Повторный запуск ничего не меняет. Посмотреть
состояние — `--doctor`, снять регистрацию — `--remove`.

Вручную для Workspace Computer это выглядит так:

```json
{"mcp": {"localrag": {
  "type": "local",
  "command": ["/абсолютный/путь/lib-local-rag/mcp_launcher.sh"],
  "enabled": true,
  "timeout": 120000,
  "environment": {"LQRAG_TIMEOUT": "110"}
}}}
```

Ключ внутри `mcp` — имя сервера. Вложенности `mcp.servers.<имя>` не существует:
агент прочитает её как сервер с именем `servers`, провалит валидацию и отбросит
конфиг целиком. У GigaCode схема другая — плоский `mcpServers.<имя>`, где
`command` строка, аргументы отдельным массивом `args`, окружение в `env`. Поля
`type` в записи нет, как и в проверенном рабочем конфиге GigaCode.

Адрес сайдкара в конфиг вписывать не нужно: мост читает порт, опубликованный
демоном в `~/.files-search/port`. Поэтому запись остаётся верной и после
перезапуска индексатора на другом порту, в том числе при `RAG_PORT=0`.

Агенту по умолчанию видны все восемь инструментов: три чтения (`local_search`,
`local_index_status`, `local_read_file`) и пять управления индексацией
(папки, почта, переиндексация) — агент в поставке остаётся единственным
пультом. Для закрытых установок write-инструменты прячет
`LQRAG_ALLOW_WRITE=0`; песочница `local_read_file` от флага не зависит.

Подробности — `docs/mcp/README.md`.

## Если что-то пошло не так

| Симптом | Причина | Что делать |
|---|---|---|
| `uv sync` тянет torch на 2 ГБ | Кто-то вернул `sentence-transformers` в `[project.dependencies]` | Убрать: модель грузится через OpenVINO, torch не нужен |
| `lancedb ... doesn't have a wheel for the current platform` | Потерялся `required-environments` в `pyproject.toml` | Вернуть `["sys_platform == 'linux' and platform_machine == 'x86_64'"]` |
| `ModuleNotFoundError: pytest_asyncio` | Ставили без группы `test` | `uv sync --frozen` (группа `dev` включает `test`) |
| Почтовые тесты падают с `assert 1 == 4` | Даты фикстуры разошлись с окном `index_last_n_days` | Проверьте `_NOW` в `tests/mbox_fixture.py` — даты должны быть относительными |
| Демон не поднимается | Нет модели или зависимостей | `/tmp/rag.log`; модель — в `models/rubert-mini-frida` |
| Поиск пуст, файлы на месте | Индексация ещё идёт | `curl /api/v1/status`, либо инструмент `local_index_status` |
| В логе `nothing new`, `total=0` | Папки меняли правкой YAML мимо API | Задать через `POST /config`, либо сбросить `~/.files-search` |
| Мост: «сайдкар недоступен» | Демон не поднят, либо порт не опубликован | `curl /health`; проверить `~/.files-search/port`; при нестандартной установке задать `LQRAG_URL` |
| Мост: «индексатор запускается или прогревается» | Демон греет модель (40–45 с). В установке из `.deb` мост ещё и сам попросил systemd поднять службу | Повторить через минуту |
| У агента нет инструментов | Относительный путь или нет прав | `python3 scripts/register_mcp.py` — подставит абсолютный путь и вернёт `+x`; затем перезапуск агента |
